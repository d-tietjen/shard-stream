# Negative query source observations

`EngineHandle::observe_query_lineage` reads the actual coordinator source during an initial blocking capture. It returns an opaque observation retaining the same ordinary or complete recovered engine owner. It neither authenticates assignments nor proves indexed replay, query completeness, current control, write permission or HA readiness.

A host must capture before its genuine checkpoint/policy/epoch checks and recheck every saved observation and full assignments after the complete capture. Keep the original deadline and physical task. Save that one proof; do not recapture after failure or use a fresh observation to renew an old proof. At request time `is_current_for` performs one atomic load and owner/partition comparisons. Recheck after retaining the complete real result, before success publication. A successful check linearizes before any later mutation; it is not a permission guard through a later network write. Streaming and actual SDK/private response integration remain host work.

The real coordinator changes a partition's revision before ring/policy/retention journal effects, admitted leader-epoch changes, or new/revived replica state. An active unit stays in the actual reservation until the physical worker's complete or definite-no-write failure reaches the coordinator. Legacy epoch activity is retained across the following reservation RPC. Unknown/missing results, unwind, counter exhaustion and atomic contention deny observation without refusing ordinary writes. The packed counter never resets or wraps; old observations never become current again.

Normal same-epoch indexed leader append, immutable duplicates, atomic decisions, same-source sink progress, sync and logical-source-preserving physical GC keep their existing behavior. Non-no-op truncation conservatively invalidates. Startup recovery creates a new source with the real partition owner; it cannot renew an existing retained owner. An opaque observation has no constructor, mutable counter, owner extractor or refresh method.

The only new engine-owned heap object is one `Arc` allocation per real partition: its packed native atomic word and two native reference counts. Native recovery prepays it in `recovery_coordinator_bytes`; actual expanded partition, batch and coordinator command layouts remain included in existing `size_of`-derived fees. Activity handoff uses a bit in the existing batch record, with no new per-write allocation, map, worker, physical guard or write permission. Capturing is an ordinary coordinator RPC, not a strict native-work producer; it must not be placed on async request threads or relabeled as a bounded owned-host qualification.

This API is a negative fact for a composing host. Public RF1 contracts, authentication, ordinary append and existing HA refusal remain separate. The engine-only tests execute real control/WAL/sink/reservation/fetch producers; they do not qualify a private host or native protocol integration.
